# AI Customer Support Intelligence

[English](README.md) | **Русский**

[![CI](https://github.com/makltd123/support-intelligence/actions/workflows/ci.yml/badge.svg)](https://github.com/makltd123/support-intelligence/actions/workflows/ci.yml)

Мультиагентная RAG-система, которая анализирует тикеты службы поддержки и собирает PDF-отчёт из трёх разделов: главные проблемы, пожелания клиентов и тональность обращений.

## Как это работает

```
Вопрос ──► Синтезатор (Mistral) ──┬──► Агент «Проблемы»     ─┐
                                  ├──► Агент «Пожелания»    ─┼──► Qdrant: 20 похожих тикетов
                                  └──► Агент «Тональность»  ─┘    (эмбеддинги mistral-embed)
                                                │
                                                ▼
                                   PDF-отчёт + веб-интерфейс Gradio
```

- **Синтезатор** — LLM-оркестратор. Он в цикле выбирает, какой агент вызвать, и отвечает в формате JSON. Цикл ограничен по числу шагов; если модель ответила не JSON-ом, запросила несуществующий инструмент или закончила раньше времени, недостающие разделы добираются вызовом агентов напрямую. Отчёт из трёх разделов возвращается всегда.
- **Агенты** ищут в векторной базе Qdrant 20 тикетов, ближайших к вопросу. Отвечают только по найденным тикетам и указывают их номера как источники.
- **Индекс** построен по случайной выборке из 10 000 тикетов.

## Стек

Python 3.11+ · Mistral AI (`mistral-small-2506`, `mistral-embed`) · Qdrant Cloud · Gradio · reportlab · pandas

## Пример отчёта

[docs/example_report.pdf](docs/example_report.pdf) — ответ на запрос «сделай полный анализ проблем в категории авторизации».

Чтобы посмотреть, как выглядит PDF, ключи не нужны:

```bash
python examples/demo_report.py   # -> demo_report.pdf
```

## Запуск

Все команды выполняются из корня проекта.

**1. Зависимости**

```bash
python -m venv .venv
source .venv/bin/activate     # Linux / macOS
.venv\Scripts\activate        # Windows
pip install -r requirements.txt
```

**2. Ключи.** Скопируй `.env.example` в `.env` и заполни:
- `MISTRAL_API_KEY` — ключ из [console.mistral.ai](https://console.mistral.ai);
- `QDRANT_URL` и `QDRANT_API_KEY` — адрес и ключ кластера в [Qdrant Cloud](https://cloud.qdrant.io) (бесплатного кластера хватает).

Остальные переменные необязательны, их список и значения по умолчанию — в `.env.example`.

**3. Данные.** Датасет в репозиторий не входит (74 МБ). Подойдёт любой CSV с колонками `category`, `issue_description`, `resolution_notes`, `priority`, `status`, `customer_satisfaction_score`: положи его в папку `data/` под именем `customer_support_tickets_200k.csv` или укажи путь в `DATASET_PATH`.

Нет датасета под рукой — сгенерируй синтетический:

```bash
python examples/make_sample_dataset.py --rows 300
```

**4. Индекс** (один раз):

```bash
python src/prepare_dataset.py   # выборка 10 000 тикетов -> data/sample_10k.csv
python src/embeddings.py        # эмбеддинги -> data/embeddings.npy (около 10–15 минут)
python src/qdrant_upload.py     # загрузка в Qdrant
```

`src/embeddings.py` сохраняет промежуточный результат, поэтому после обрыва его можно просто запустить заново — он продолжит с места остановки.

**5. Анализ**

```bash
python src/app.py               # веб-интерфейс на http://127.0.0.1:7860
python src/agent_synthesizer.py # или сразу отчёт report.pdf по запросу из кода
```

## Тесты

```bash
pip install -r requirements-dev.txt
ruff check .
pytest
```

Тесты не обращаются к сети и не требуют ключей. Для сборки PDF нужен системный шрифт с кириллицей (на Ubuntu: `sudo apt install fonts-dejavu-core`).

## Ограничения и что стоит знать

- **Качество данных.** Публичный датасет, на котором всё проверялось, синтетический: тексты собраны из шаблонов, многие тикеты совпадают дословно, а категория не всегда соответствует описанию. В примере отчёта у всех 20 найденных тикетов одинаковый текст. На таких данных выводы агентов выглядят правдоподобно, но мало что значат.
- **Выборка, а не полный анализ.** Агенты видят только 20 ближайших по смыслу тикетов, поэтому «топ проблем» — это топ внутри выборки, а не по всей базе. Для настоящей агрегации нужна кластеризация по всему корпусу.
- **Фильтров нет.** Категория, период и приоритет в поиске не учитываются — только семантическая близость.
- **Содержимое тикетов попадает в промпт.** Агентам явно сказано считать текст тикетов данными, а не инструкциями, но на реальных клиентских данных это не полная защита от prompt injection. Персональные данные в тикетах перед индексацией стоит обезличивать.
- **Шрифт.** PDF требует TTF с кириллицей. Система ищет его сама (DejaVu, Liberation, Arial, Carlito, Noto); путь можно задать через `REPORT_FONT_REGULAR`.
